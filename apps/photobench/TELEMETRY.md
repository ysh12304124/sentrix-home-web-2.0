# 遥测记录方式

配置文件为配置根目录下的 `telemetry.json`，通常位于
`apps/photobench/config/telemetry.json`：

```json
{"history_enabled": false}
```

文件缺失时也默认关闭。字段必须是 JSON 布尔值，不能写成字符串。
服务启动时读取配置，每轮任务准备时保存记录模式；修改文件不会改变正在运行的任务。
发布和重新加载服务应在确认空闲后进行。

关闭时，各项指标覆盖保存最新读数，独立实时快照约每两秒原子替换一次；
不追加历史 JSONL、不保留时间曲线。后台用固定大小的计数器保留全程峰值、
均值、有效样本数及采样间隔、缺口和阶段计数，统计不再扫描全部历史。
详情接口也不读取旧任务的历史文件，避免打开已有大文件再次引起内存峰值。

开启时，原始明细追加到 `gpu_samples.jsonl`，内存窗口最多 240 点，
详情曲线逐行读取并均匀抽样为最多 240 点。图表可能省略短暂变化，
全程统计独立累计，不从抽样曲线反推。应按需开启长时间原始记录。

新任务的两种模式均使用增量统计，不保留完整分布，精确 P50/P95 标为未记录。
资源遥测协议的均值沿用有效相邻点的梯形时间加权，跨阶段、缺失值及超过三秒
的间隔不计入覆盖时间和能量；旧协议仍采用样本均值。未观察到空闲基线时，
不再以中位数代替空闲内存估计。

旧任务、原始历史文件和正式评测结果不删除、不迁移。关闭配置时只显示
最新读数与已保存统计；重新开启后可读取旧曲线，旧协议仍沿用原统计逻辑。
显式开启后读取旧的大型历史文件仍可能产生旧解析路径的开销，
不把本次对新任务的内存上限解释为旧历史已全部改造成有界解析。

本配置只控制遥测，整机内存的统计定义、模型 KV 缓存和推理参数不随之改变。
