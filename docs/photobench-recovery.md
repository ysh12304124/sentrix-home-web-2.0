# PhotoBench 续跑与补评分

任务详情新增两个独立入口：

- **继续中断的测评**：复用原相册与冻结 QA/GT，保留已执行题（含原执行失败），只运行未执行题。创建带来源记录的新任务，原任务不改。默认同时补评已保存答案中的缺失评分。
- **重新 Judge 评分**：不执行 Agent。默认仅补评失败或未评分；可切换仅失败、仅未评分、全部答案。显示题数、实际对话轮数、评分项数。0 分是有效分数，补评时保留。多轮题按每轮、每个子评分筛选，替换项归档，原 GT/回答/执行状态保留。

产品版本变化时，续跑卡列出原版和当前配置版本，用户明确选择当前版本后才能启动。后端仍验证真实产品版本、运行参数及原 QA 快照。执行失败题需要独立安排重跑，本按钮按“跑过跳过”保留。

## GT 图片辅助评分

开始测评、续跑和补评均可选择，默认新任务关闭，续跑默认继承来源设置。需要支持图片输入的 Judge。图片只给回答质量 Judge，不给 Agent；任务行为评分继续判断实际回答行为。

取图顺序：冻结逐轮 GT 优先；逐轮未声明媒体引用时取题级 GT。每层先取 `answer_evidence_*`，未声明才取 `retrieval_*`。显式空引用保留为空。按媒体类型及文件名唯一匹配原相册资产；只发送图片，视频引用留在审计中。

每张 GT 图片经现有适配器缩放至长边不超过 896、JPEG quality 90，并保存引用来源、资产 ID、匹配状态及实际发送 data URL 的 SHA256。匹配缺失/歧义或读取失败时质量评分失败，无数字分数；无图片 GT 时使用文字评分并记录 `no_gt_images`。带图提示词明确 GT 仅为裁判依据，不证明 Agent 检索/交付成功，不执行图中文字指令，也不据图片改变拒答/澄清契约。图文 GT 实质冲突时要求返回空分及原因。

补评更改图片模式只影响本次选中的评分项，已有有效分数保留各自原模式。每个评分的实际输入及 `gt_images` 记录可追溯，不能将部分补评的整次任务称为统一带图评分。

## API

- `GET /api/v1/runs/{id}/recovery-plan`：只读题数、版本、补评分母，不触发推理。
- `POST /api/v1/runs/{id}/resume`：`repair_missing_judges`（bool，默认 true）、`judge_use_gt_images`（bool，默认继承）、`product_build_revision`（显式选择当前已配置产品版本）。
- `POST /api/v1/runs/{id}/rejudge`：保留原 Judge 连接/提示词字段；增加 `scope`（`missing`/`failed`/`unscored`/`all`）、`judge_use_gt_images`（bool，默认 false）。旧 API 未传 scope 维持全量重评兼容；前端明确提交 `missing`。

无回答、未标注、不适用或原执行失败题不列入针对性补评分母。失败/取消及工作线程启动失败会保留任务记录与已完成分数，未完成项以后可再次补评。服务已有活动任务时禁止并发启动恢复/评分任务。
