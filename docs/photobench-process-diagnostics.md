# 答题过程诊断

规则版本`answer-process-v1`。该功能从已有冻结题目、答卷、候选身份和工具轨迹生成观测，单独存入结果根目录的`.process-diagnostics/<run_id>.json`。原答卷、原执行状态与正式评分不变；读取不调用Agent或Judge，也不加载完整遥测历史。

`GET /api/v1/runs/{run_id}/process-diagnostics`提供同一规则的全题汇总与逐题依据；逐题详情、trace与SFT导出带`process_diagnostics`。页面汇总和逐题诊断默认折叠，展开汇总后才请求分析；逐条保留来源路径、步骤、原始原因、对话轮、答卷与题目指纹。汇总按唯一QA统计，类别可以重叠，不能相加为失败总数。

| 类别 | 依据与限制 |
| --- | --- |
| 候选未全命中 | 只有目标定义、候选清单和全部身份映射完整才确认；未知映射显示记录不足 |
| 未记录进一步取证 | 对命中媒体没有成功读取、查看或人物核验记录；候选已有描述可能足够回答 |
| no_text | 确认文字读取没有文本，是否影响答案待复核 |
| 参数、预算或其他工具限制 | 保存原始错误与拒绝原因，不推断底层故障 |
| 语义内容待复核 | 产品未满足要求或已有Judge理由只是复核线索，不直接认定回答错误 |
| 正式交付不全 | 仅用于需要媒体列表的题，按正式附件映射对照答案目标；纯文本题不要求附件 |
| 记录不足 | 与确认未检索、未交付分开，保留缺失字段和无法映射的资产ID |

列表评分使用答案目标集合，公共检索诊断使用检索证据集合。两类GT分别展示。媒体身份按`media_type + media_id`；已保存的`source_keyframe_asset_id`只用于将明确关联的关键帧归到父视频。冲突、缺失关联保持未知，不凭GT、最近邻或编号顺序推断。

根目标只用于冻结定义的评估轮，中间轮必须有自己的定义。原`answered_with_gap`作为独立原始标记保留。合法0分、没有附件的纯文本回答和no_text观测均不会触发自动重跑或改分。

Judge隔离小样见`apps/photobench/tests/fixtures/judge-regression/README.md`，样例不写正式评分批次。
