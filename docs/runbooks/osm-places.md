# OSM 离线地点解析

## 部署

1. 在构建环境安装 `osmium==4.3.2`，使用 API 环境里的 Shapely 2 和启用 R*Tree 的 SQLite。
2. 从 [Geofabrik 中国数据目录](https://download.geofabrik.de/asia/china.html) 选取带日期的
   区域或中国汇总 PBF，核对同版本校验文件后，运行
   `python scripts/build_osm_places.py data/geo/hebei-latest.osm.pbf data/geo/osm-places.sqlite`。
3. 将成品放入各服务的 `SENTRIX_DATA_DIR/geo/osm-places.sqlite`，重启后检查启动日志中的版本。
   每份运行时目录只加载一个地图包，可覆盖区域或全国。地图文件不进 Git；
   编译时保留多边形的组成节点和关系。

运行时只读索引，无 GPU 或联网要求。区域数据只适用于已覆盖范围。索引使用源 PBF 的 SHA-256
与索引格式版本作为版本。更新运行中的 Windows 服务时先停服务，再替换索引并重新启动。
数据来源 © OpenStreetMap contributors，按 [ODbL](https://www.openstreetmap.org/copyright) 使用。

## 解析规则

中国省、地市、区县、乡镇街道、村社区分别用 OSM 行政面；行政边界 10 米内或同级候选
冲突时不认定该级。区县缺失时可使用 PyGeoCN 粗归属。乡镇或村界命中时优先显示行政面，
景点面命中时优先显示景点面；只有对应类型没有包含 GPS 的面，才在 1.5 公里内取最近的
居民点或景点点位。面候选存在但相互冲突时，保留该字段的不确定性。道路在同样半径内取
距离 GPS 最近的有名路段。
v4 索引把 `ISO3166-2=CN-MO` 的 `admin_level=3` 边界写入省级字段。澳门由本地边界
给出省级归属，已有下级地点继续独立解析，地市可以为空。香港沿用已入索引的行政层级。
道路索引保留 `name` 和同一要素的 `ref`。无名称道路不入新版索引，反查与词法投影只返回路名。
旧版索引中的纯编号候选也会被排除。新版场所索引也收录有名的
影城、咖啡店、度假村、住宿与教育设施。这些字段是拍摄地点线索，不用于判定行政归属。
点和线均只写「附近」，景点面命中仅说明 GPS 落在范围内。GeoNames 不再装配，历史结果仍可读取。
已保存证据带 OSM 对象 ID 和索引版本；地点词法索引使用新名称，结构化行政统计仍按省市区县。

## 已有相册及验收

使用 `scripts/validate_osm_places.py` 的 `--db --index --scope --metadata --output`
对现有相册逐媒体预测与对照，输出缺失、同名、冲突和层级差异。GT 只参与比较。
评测读取原始地址与 PyGeoCN 自带的行政区划名称和编码，纠正可确认的区县误入 `city`，
无法确认的标为待核对。澳门地市记为不适用。报告保留原始结构化参考值及归一化状态。
比较道路阈值时在同一相册和同一地图版本重复执行 `--road-radius 30`、`60`、`100`、
`1000`、`1500` 或 `2000`，分别保存结果。召回率的分母是有道路标注的素材数量，
返回结果中不一致的占比以有标注且返回道路的素材为分母。无道路标注的素材计为未知。
Album3 的地名参考包含 Nominatim 标签，视频对照来自所有源照片共有标注，二者的统计
不等价于对独立人工 GT 的场所准确率。

使用 `scripts/backfill_osm_places.py --db ... --index ... --scope ...` 预览命中，或使用
`--all` 处理指定数据库内的全部相册。
确认没有其他写入任务后加 `--apply --backup <新备份路径>`，更新该相册命中的资产地点及
观察词法投影。可用 `--changed-only` 跳过仅地图版本变化的资料。
当事件原地点来自 GPS、关联资料均解析到同一地点且事件未经人工修正时，
一并更新该事件的时间线地点。无 GPS 或无 OSM 命中的记录保留。历史事件摘要、事件归组和
图边需要另行审核后更新。回滚时停服务，从备份恢复对应数据库及投影。
