# 跨相册媒体文件共享

同一产品实例的 `media_dir` 内，相同 SHA256 的原始媒体只保存一份内容。
每个相册仍有自己的资产 ID、路径和处理结果；搜索、权限、记忆及删除记录按原相册隔离。
照片、视频和音频的原件都走共享存储。不同实例的独立媒体目录各保存一份。

## 文件组织与删除

内容保存在 `media_dir/.blobs/<sha256>`，资产路径沿用 `{asset_id}_{原始文件名}`，
通过硬链接指向内容。硬链接是文件系统中指向同一份数据的多个名字，不额外复制文件内容。
操作系统维护引用数量。移除一个资产路径后，其他相册继续读取；最后一个资产引用移除后，
内容文件被回收。所有存储实例和进程通过同一文件锁协调发布与回收。

该实现使用 macOS / Linux 的文件锁与硬链接，媒体目录所在文件系统必须支持硬链接。
外部源目录始终保留独立文件，防止用户编辑源文件后改变已经导入的内容。
后端不得原地修改受管原件；修改后的内容应作为新的资产导入。

新增相册不会复用已有相册的识别、向量或图谱结果，媒体理解和派生视频文件仍分别生成。
共享消除的是原始媒体的重复副本，数据库和派生文件仍会随测评增加。
列表中的 `size_bytes` 表示每个资产的逻辑大小；上传配额按实际设备号和 inode（文件身份）去重。
上传接收期间仍需要单文件暂存空间和上传预留配额。

## 已有数据

目录导入会用 SHA256 定位已登记原件，直接纳入共享存储。原路径及数据库记录保持。
已有多份历史重复文件，可用维护脚本批量合并。该脚本默认只读，逐文件检查 SHA256，
报告重复内容与可回收文件字节数。缺失或外部源文件列出并保留；哈希不一致时停止。

先核查实际实例使用的数据库和媒体目录：

```bash
PYTHONPATH=apps/api/src python scripts/maintenance/consolidate_media_files.py \
  --database /absolute/data/sentrix.db --media-dir /absolute/data/media
```

确认维护窗口、停止该实例的导入和处理后，在同一命令末尾加 `--apply`。
脚本只替换已登记原件的硬链接，不更改数据库、资产 ID、相册关系或文件字节；
可中断后继续执行。完成后再运行默认核查，`reclaimable_file_bytes` 应为 0。
维护其他服务器时，按项目约定先同步本机已验证并提交的代码。

## 故障恢复与验证

原件先完整写入暂存文件并同步磁盘，再发布内容文件与资产引用，不暴露写到一半的资产。
体验模式的启动对账在宽限期后回收没有作业或资产引用的文件，
并回收只剩内容库自身链接的孤儿内容。独立 API 的启动行为保持原有设置。
判断宽限期使用修改时间与状态变更时间，避免旧内容的新硬链接被误删。

`ls -l` 会对每条硬链接显示完整逻辑大小；判断是否共享，可用 `stat` 核对设备号、inode
及链接数，或用默认会去除硬链接重复计数的 `du` 检查整个媒体目录。
针对共享存储的回归在 `apps/api/tests/integration/test_shared_media_storage.py`。
