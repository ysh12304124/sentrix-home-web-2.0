# 列表评分与正文编号对照

ATM-Bench式QS保持两种汇总，均按全部QA逐题等权平均。

| 名称 | 列表题使用的集合 | 其他题 |
| --- | --- | --- |
| 模型交付口径QS（主QS） | 模型正式交付的图片、视频集合 | 当前批次的原分数 |
| 工具候选口径QS | 工具候选全集，不截取前5份 | 同一批次的原分数 |

列表分都是`|预测集合∩冻结GT| / |预测集合∪冻结GT|`。正文提到媒体编号，不会把该媒体补入正式交付集合。R@5和媒体P/R/F1继续独立展示。

## 正文编号对照

逐题结果中的折叠面板展示三种来源的Jaccard。新增的正文结果只用于对照旧版正文ID口径，计算时读取保存的答卷，不调用Judge，不写入评分批次，不改变历史总分。

- 只识别正文明确出现的时间格式媒体ID、`asset_...`和`photo_N`等编号。
- 别名按保存的工具预览、媒体身份或交付记录映射；GT只用于最后集合比较，不用于猜测编号身份。
- 映射冲突、无法识别编号、缺少冻结GT或正文只有描述时，显示无法完整计算；不将缺失信息记为0。
- `photo_1 到 photo_5`等范围不自动展开。面板保留已解析编号和未解析原因。
- 明确写出的完整媒体文件名可以作为预测ID；不在GT中的ID仍参与并集，避免漏计多选项。

这不是历史评测器的完整复现。旧版可能还对没有ID的文本列表进行拆分，且原GT或ID映射方式可能不同，不能将本诊断分直接作为旧版总分。

API逐题结果及两个导出格式通过`profile_scores.atm_qs_v1.list_comparison`提供同一诊断。按标准、批次投影后的`evaluation_result.list_comparison`也提供对应记录。诊断版本为`answer-text-ids-v1`，`diagnostic_only=true`。

Judge默认连接由部署私有配置保存。更换默认模型只影响未来任务和新评分批次，已启动任务及历史批次继续使用冻结配置；不将部署地址或凭据写入代码。
