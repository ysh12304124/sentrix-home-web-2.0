# 人物页标签、上传和关系图排查（截图后修正）

## 选中标签

用户截图明确指向人物页内的选中标签。experience.css 的背景是 --ex-forest，
主题映射将它变成 --ui-accent；themes.css 又将选中文字设为 --ui-accent，
导致文字与背景完全同色。修复为明确 accent 背景与 on-accent 白字。
三个主题按实际加载的样式级联计算文字/底色，回归测试要求对比度 >=4.5。
此前猜测为窄屏顶部导航隐藏，已撤回那部分 AppShell/shell/family 布局修改。
Safari 截图自动化仍不可用，不把 CSS 测试冒称浏览器截图验收。

## 上传未处理

截图时 SQLite 有 1894 条 import_jobs 全部 accepted、attempts=0、没有阶段记录。
上传接口无论部署模式均写入持久作业，但 build_import_executor 在非 experience_mode
返回 None，所以本机 8191 接收后无人领取。修复为独立实例也装配既有执行器。
不改变整个 experience_mode，不改控制面认证、不启动体验问答执行器、不启用媒体清理。
现有同步导入入口仍保持原契约。前端把涵盖 accepted/queued 等状态的统计改称
“排队或处理中”，单条任务仍显示真实状态。

使用临时数据库和合成 PNG 经真实上传接口与仓储验证：accepted -> completed，
资产 processed、观察记录落库；模型依赖使用测试假件。真实服务重启后已见
1890 accepted、4 running，四条 asset_staged=done、prepared=running。
后续完成统计以实时数据库为准，不宣称 1894 条已经全部处理完。

## 关系图与上传续传

此前关系图接口确实返回空人物；当时七个空间均为 benchmark 且不展示。
用户明确选择保留评测隔离，等待真实照片。新上传任务尚未消费也是没有新人物的原因。
实际照片处理并产生可确认的人物后，用户可确认身份、在详情建立同空间关系。
不把测试空间改为家庭空间、不凭同名推断关系。
截图的“14 个文件未完成上传”是浏览器侧未完成记录；服务端不能处理尚未接收的文件。
用户需重新选择原文件夹，既有去重机制跳过已上传部分。
