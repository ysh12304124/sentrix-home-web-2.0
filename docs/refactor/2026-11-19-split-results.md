# PhotoBench 分块结果与按需读取

2026-11-19，本轮只发布 100 的 8872/8874 测评服务。

## 数据与读取

`PHOTOBENCH_SPLIT_RESULTS=1` 采用格式 3。SQLite 保存按内容哈希引用的不可变 JSON 对象，长字符串按 32768 字符分块；每次检查点只新增变化对象，并原子发布 `split-commit.json`。原始状态树完整保存，概览、题目目录、单题核心、节点目录分别保存。指标计算投影不改变原始答卷和轨迹。已保存轨迹从活动状态替换为磁盘引用，评分元数据继续可变。

列表和概览只读取指标；题页只读取目录；单题只读取核心及预计算诊断的前20条预览；完整诊断经内容接口按块读取。节点目录每页最多 50 条；点击节点后才请求内容，每次最多 65536 字符，按实际 JSON 字节控制到 256KiB 内。翻页替换当前内容，节点和内容请求固定读取版本。Judge 原始请求通过独立节点访问；长答案提供明确的完整内容入口。

模型输入输出、工具原文、失败记录、评分批次都保存在原始树。trace/SFT 两种下载按题流式生成，并复用同版本诊断；HTTP 合并细小 JSON 片段后发送。内容指纹、指标投影与节点目录按不可变输入在磁盘复用，重启后继续使用。指标投影使用64MiB有界缓存，避免相同轨迹在每次保存时逐字段重复解析。

## 历史记录

格式 3 下，HTTP 不自动解析尚未迁移的旧完整文件。旧原件保留，先显式建立派生索引：

```sh
PYTHONPATH=apps/photobench/src python -m photobench.infrastructure.results.index_legacy \
  --results-root /path/to/results --run-id EXACT_RUN_ID
```

迁移用 Python 保留原始数值类型的 JSON 流读取与 gzip 解压，逐个容器写入内容引用，不构造完整的 GB 级状态；完成后核对源文件身份、SHA256，再发布索引。转换必须在精确源 run 的 worker 已结束后执行。其他已完成历史可在独立维护窗口迁移，服务请求不会触发该操作。

本轮延续已有 18 题隔离标记，只在原 scope 内继续未完成题，保留有效分、失败历史和 1013 分母。

## 发布与验证

新脚本 `deploy/photobench/20261119-full-lazy/publish.py` 的每一步保存独立 intent/response。候选构建和测试可在现役测评期间执行；取消精确 run 后必须确认 worker、对应产品 turn 与导入 pipeline 空闲，才迁移最终检查点、切换两个测评服务。新 wake 登记先于新 resume。旧发布脚本不再执行。

`verify_long_run.py` 使用包含全部异常轨迹的真实 101 题存档，检验 48 路读取与 4 路保存、原答案/评分元数据及两种完整导出。结果与内存实测写入产品项目 `audit/20261119-full-lazy-results/`。代码测试、压测、候选验收和生产验收分别记录，不能互相替代。

真实101题（含全部18条超长轨迹）复测：48读/4写，120秒请求窗口，942次读取/4次提交；峰值RSS1669021696字节，保存最长150.54秒，摘要最大96033字节。读取测量包含概览、完整题目录、核心、节点页及一块内容，整组最长15.92秒；HTTP接口另行在线验收。trace为27569451字节、SFT为3584890256字节，修正前后导出SHA一致，答案/评分元数据指纹保持。早期664秒保存和2.3MB诊断摘要的问题已记录并修正，不能将其失败记录删作成功。

Qwen续评验收发现旧迁移工具会把0.0等浮点值转为整数0，导致两条包含视频时间字段的答卷指纹失配。迁移解析改为Python流式解析，保持浮点/整数及大整数类型；评分校验不放宽、原分数与原件保持。补充跨64KiB字符串边界、浮点负零与大整数的指纹一致性测试。
