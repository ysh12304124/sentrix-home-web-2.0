# 独立文本检索与邮件证据指标

## 边界

图片/视频的导入、事件归并、摘要、视觉/词法/ANN/图融合和原Agent提示词保持6b26030e基线。
文本仍以资产、观察和事件保存原文与来源ID；新增独立text_memory_chunks派生索引。
分块不走视觉/OCR，不向memory_vectors或媒体的semantic/episodic向量新增邮件块。
文本scope才广告search_text_memories及终止动作的selected_text_handles；无文本scope的
工具参数和提示词不变。混合scope分别检索，复用同一Agent框架与原文读取入口。

## 构建和检索

每块最多256字符、相邻重叠48字符，保留完整原文和精确起止offset、观察revision、
源asset_id/external_id及source_type。文本嵌入用现有TextEmbedder端口。写入前检查
revision，同一观察的全部分块原子替换；正文或嵌入失败保留权威数据并报告partial，
重复导入检查模型及revision，旧的整封索引不能冒称新分块已经完成。

检索先按scope/source_type/邮件记录时间过滤，再做词法BM25、文本余弦召回。
按源资产分别去重各通道后，复用weighted_rrf_score（k=60、文本两通道各1.0）融合，
不改媒体通道的基线权重。记录时间只是过滤条件，不证明正文所述事件时间。
文本向量以一个共享FP32矩阵缓存，最多256MiB；缓存键包含全部当前观察revision，
写入失效、删除/修正后的过期块通过关联查询排除。模型/维度变化需重建；缺索引或
查询嵌入失败明确degraded，不把未构建当作零召回成功。

新结果集持久化text_offsets；read_source_text默认从命中块起点读取，文本新路径
每页640字符并返回next_offset，避免原文尾部信息在Agent核验输入里再次被裁掉。
旧媒体/结果集的默认读取语义不变。修正重建选用独立文本索引，删除依靠观察外键级联。
分块表和结果集offset分别由0035、0036增量迁移登记，已有版本不会被覆写。

## 引用与指标

文本预览handle为result_set_id/photo_N，只供工具参数使用，正文仅引用公开external_id。
ToolPolicy只允许本回合已返回的结果集，仓储/工具再次校验scope和当前资产存在性。
selected_text_handles经服务端解析到当前源ID，去重后随trace.text_evidence保存。
text_citations_recorded区分“明确未引用”和“没有结构化引用事实”。自由文本收尾只在
文本检索成功的回合提醒一次补充final_answer，不扩大图片视频的预算或改变其收尾。
文本取证的L2另附来源元数据规则，区分公开evidence_id与内部路由handle，避免将正确
邮件ID误判为编造；未使用文本工具的回合仍使用原评审提示词。对直接把已解析的内部
handle写成公开来源的回答，仅提醒模型重答，不做字符串替换或出口清洗。

PhotoBench从数据集retrieval_media_refs（邮件证据GT）计算检索P/R/F1与R@1/5/10，
从answer_evidence_media_refs计算最终引用P/R/F1。跨调用候选以首次出现的顺序保序
去重，多个块/重复查询命中同一邮件只计一次；检索和引用不得相互回填。
指标只读取运行时来源事实，不从答案文字猜邮件ID；产品不读取GT或benchmark题面。
旧记录缺取证事实时显示unavailable，不能补成0分或100%。汇总分别记录题数、可计算
样本数、与原有指标相同的逐题等权P/R/F1及macro R@K；新字段均增量可选。旧的图片/视频R@5公式不变。

## FTS5、关联池与文本模型重排

0037迁移新增源级FTS5及revision关联投影；不重复计算已有分块向量。
FTS在完整原文上匹配、BM25按摘要/正文4:1加权，再与向量源排名做RRF。
主题、同一线程/预订标识及有界实体词组建立可重建关联键，原文修正和删除后失效。
前3个种子最多各扩展2封同scope且满足来源/时间限制的邮件；主题与实体链接限定30日，
高于8封的窗口枢纽不扩展。扩展仅是候选关系，不作为“真实因果/事实关系”展示。
扩展条目进入头部重排池，RRF名单与扩展名单分别记录，不使用GT建立边或筛选候选。
保留RRF排序，不再用归一化BM25+余弦覆盖它。只有重排输出有效才采用模型顺序。
本机无交叉编码侧车，因此复用现有模型通过结构化JSON评相关性；该重排是模型评分，
不得标成cross_encoder。配置了已有重排侧车的部署则复用端口。每次最多24条、返回6条。
时间不盲目硬过滤：将原问题的“今天”等上下文给重排，区分发信日期和正文活动日期。
来源复合别名兼容与日期整日上界经过测试；有歧义的来源表达式明确报错。
复用模式跳过邮件重导入/图重建；全文和关联补齐在当前scope首次读取时原子进行。

专项验证：37个分块/邮件导入/来源/重排/修正删除用例已通过（无skip）；5个生产模块
strict类型通过。真实BGE+本机模型在6742封邮件的隔离副本上完成两次排序，旧的跨年份
活动和申请截止日期漏召回题，目标来源均到第1位，rerank=text_model_relevance_v1，
无degraded。证据text-fts-real-ranking.json/log位于忽略的数据目录。
仅做专项验证，不替用户启动381题正式测评，不承诺整体分数。完整CI遗留失败仍按前文披露。

## 复用阶段状态展示

PhaseList只在文本阶段实际执行（running/done/failed/partial等）时映射文本构建卡。
复用模式下text_memory_import为skipped、pending或缺失时，导入/流水线显示跳过，
不因email_only_qa强制生成“读取中”或“等待构建”。全链路尚未开始的阶段显示等待；
历史真实执行及失败保持展示。前端只读投影，不改运行状态，不取消或重启当前测评。

文本导入最后一批实收计数先落进度。全部文本索引完成且图已保存、仅因果边降级时，
文本阶段保留部分完成与因果告警，继续 QA。真实索引失败或图写入失败仍中止。
续跑失败或中断在文本阶段的记录时，在原相册幂等复查文本，最后一批构图后再进入 QA。
已索引原文复用现有幂等检查，普通复用相册和图片视频流水线沿用原行为。
