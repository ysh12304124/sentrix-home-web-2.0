# 2026-10-29 资源遥测与流水线展示调整

用户要求把资源信息集中到实时资源遥测，并补充峰值、P50、P95，核查流水线步骤。仅修改 PhotoBench 前端；产品执行、采集公式、接口响应与历史结果保持原记录。

## 展示与统计

- 移除结果区独立的“GPU 指标”“可比较显存”卡片。旧协议独有的统计与显存画像放入遥测内折叠的“历史采样汇总”，保证仅有历史画像的记录仍可查看。
- 当前 resource_telemetry_v1 的内存、显存、利用率、温度和功率指标下，逐行展示采样峰值、P50、P95。大字仍为最后有效记录中的当前值，某次采样缺失不冒用峰值补齐。
- 优先采用后端完整采样统计。旧记录只有完整历史时才计算分位数；抽稀或窗口数据不得推算全轮分位数。缺失统计为“未记录”，0 为有效数值。
- P50 沿用后端 sorted[n//2]，偶数样本取两个中间值的较大者；P95 为 nearest-rank sorted[ceil(0.95*n)-1]。排除无效值，按采样点统计，非时间加权分位数。缩放曲线不改变统计。
- 前端 field_stats 类型补上后端已有的 p50 字段。未新增 API。
- 图表实例销毁时清空绘图版本缓存，使开发模式 StrictMode 重放 effect 或热更新后，新实例正常绘图。

## 流水线范围与计时（用户后续修订）

素材导入仅展示文件登记、去重、元数据读取、预览准备和落库。画面理解、向量、人脸、事件、图谱与画像均放在流水线卡。旧合并请求的处理进度、prepare/finish/summarize及收尾计时也统一放入该卡；导入摘要仅保留登记计时，并指向历史合并请求说明。原run数据不变。

流水线展示分为：

- 实际总耗时：优先用阶段finished_at-started_at；运行中采用当前已用时间。没有完整起止时标“记录耗时”，不把旧total_seconds自动称为墙钟。
- 后端处理耗时：timings.total。与请求起止的差额未细分，不冒称全部是网络耗时。
- 媒体处理与事件总结：timings.pipeline_core为整段实际耗时；下面源媒体模型准备为并行任务累计，提交、视频处理为串行累计，事件总结为批末实际耗时。不同任务的准备与提交会重叠，不相加成总时延。
- 视频场景与关键帧处理：video_total为包含项。可展开已有的video_scene_planning、video_scene_write、video_keyframe_extraction、video_keyframe_asset_write、video_keyframe_memory，补齐原先漏展示的三项。
- 图谱与人物收尾：参与者投影、记忆图构建、家庭图谱、人物画像依次执行；因果边判定缩进标为记忆图的包含项。
- 只为pipeline_core及收尾的顶层串行步骤计算“占后端”百分比，分母timings.total。累计任务及包含项不计算该占比；缺失/非法/超出分母时不输出。
- 可用的历史调用均值/P95、并发、吞吐折算另组展示；显式运行有这些字段时也保留。图片折算均值明确不是单图真实时延。

显示层读取产品已采集字段：ProcessAlbumPipeline、ImportAssets.prepare_image/commit_image、ExtractVideoScenes及timeline路由收尾。源资产累计仅覆盖成功返回timings的资产，失败资产可能没有计入；不得将累计时间解释为完整失败成本。场景规划等视频字段来自已有接口，没有新增采集。

旧接口timings.prepare按当前源码是主线程future.result等待累计，不能当成worker模型耗时。旧请求同时登记和处理，其独立墙钟无法拆回；保留合并范围说明。所有缺失保持未记录/待回传，0有效，非法负数及非有限值不参与展示。

当前画面理解、人脸检测、向量等更细子步骤共用准备/提交计时；只有历史stage_timings确实保存时才展示独立调用统计。本轮不补造这些细分，也不改产品执行链或下游轨迹代码。流水线整卡全宽，时间、口径和处理内容分列，长时间用时分秒显示。
