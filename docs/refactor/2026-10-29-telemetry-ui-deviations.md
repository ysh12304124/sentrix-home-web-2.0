# 2026-10-29 资源遥测与流水线展示调整

用户要求把资源信息集中到实时资源遥测，并补充峰值、P50、P95，核查流水线步骤。仅修改 PhotoBench 前端；产品执行、采集公式、接口响应与历史结果保持原记录。

## 展示与统计

- 移除结果区独立的“GPU 指标”“可比较显存”卡片。旧协议独有的统计与显存画像放入遥测内折叠的“历史采样汇总”，保证仅有历史画像的记录仍可查看。
- 当前 resource_telemetry_v1 的内存、显存、利用率、温度和功率指标下，逐行展示采样峰值、P50、P95。大字仍为最后有效记录中的当前值，某次采样缺失不冒用峰值补齐。
- 优先采用后端完整采样统计。旧记录只有完整历史时才计算分位数；抽稀或窗口数据不得推算全轮分位数。缺失统计为“未记录”，0 为有效数值。
- P50 沿用后端 sorted[n//2]，偶数样本取两个中间值的较大者；P95 为 nearest-rank sorted[ceil(0.95*n)-1]。排除无效值，按采样点统计，非时间加权分位数。缩放曲线不改变统计。
- 前端 field_stats 类型补上后端已有的 p50 字段。未新增 API。
- 图表实例销毁时清空绘图版本缓存，使开发模式 StrictMode 重放 effect 或热更新后，新实例正常绘图。

## 流水线范围

显式流水线固定展示十项：源媒体模型准备、源媒体记忆提交、关键帧提取、关键帧记忆构建、事件总结、参与者投影、记忆图构建、因果边判定、家庭图谱、人物画像。

核查依据为产品 ProcessAlbumPipeline、ImportAssets.prepare_image/commit_image 及 timeline 的流水线收尾：视觉向量、画面理解和人脸检测属于模型准备；地点、事件归属、文本向量、实体和事实属于提交。按当前配置启用的子步骤共用阶段计时，无独立耗时不能拆造数值。

- 十项按产品 timings 展示；运行中缺失为“待回传”，结束后缺失为“未记录”，不可由缺失判断跳过、完成或失败。视频两项注明“仅视频适用”。源视频数量/逐步骤执行状态未在此响应完整提供，因此不会仅凭 video_scene_count=0 标“未涉及”。
- 累计 worker 耗时可能超过墙钟；因果边耗时包含于记忆图构建，不叠加求总时长。
- 旧合并流水线保留有值的图片均值、并发及细分统计，移除无值空卡；事件耗时与事件调用数用不同标题，避免同名卡片。截图中的图片均值和并发是统计，不是额外步骤。
- 流水线卡独占一行，十项按宽度自适应排列。
