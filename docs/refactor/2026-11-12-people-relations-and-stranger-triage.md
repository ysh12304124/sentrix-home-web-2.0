# 人物页：别名编辑、关系建立与陌生人分流

分支：`feat/people-relations-and-stranger-triage`（基于已合入 PR #30 的 main）。

## 1. 别名 / 姓名编辑

- 别名编辑增加「取消」，恢复打开时的原文并退出；`Enter` 保存、`Esc` 取消；打开时自动聚焦。
- 已确认人物的姓名框同样支持：改动后出现「取消」，`Esc` 回到原名；未改动时「保存姓名」不可用。
- 快捷键统一在 `family/editKeys.ts`：输入法组字（`isComposing` 或 `keyCode 229`）时两个键都交给输入法；
  `Esc` 不冒泡，避免外层侧栏一并关闭。

## 2. 人物关系

**诊断：数据本来就是双向的。** `set_relationship` 一次写正反两行，两侧档案都读得到同一条关系。
问题在详情的显示：它显示的是「我自己的称谓」而不是「对方是我的什么人」。设了「王王 是 明明 的父亲」后，
明明的档案里显示「**儿子** 王王」，读起来像王王是儿子，于是看起来只写了一边。

改动：

- 关系列表写成整句「王王 是 明明 的父亲」，并带对方头像。称谓取法见 `membership.ts` 的
  `relationFromSelf`：我是主语取 `inverse_predicate`，我是宾语取 `predicate`。
- 建关系改成一句话：「[对方] 是 [我] 的 [称谓]」。称谓按长辈 / 同辈 / 晚辈 / 其他分组，覆盖后端白名单的全部称谓（原来只有 11 条组合）。
  - 反向称谓自动推出。父母、祖辈等需要区分性别的情况，才多问一句「我是 TA 的 儿子｜女儿」。
  - 兄弟姐妹按长幼收窄：对方是哥哥时，我只能是弟弟或妹妹。
  - 提交前预览两句话；对方已有关系时提示「将替换现有关系」（后端本来就是替换）。
- 「选择对方」从纯文字 `<select>` 换成 `PersonPicker`：
  - 每项带头像、名字、「待确认 / 路人」标签和出现次数；
  - 可按名字或别名搜索；
  - 偶遇面孔默认收起。
  - 「与其他人合并…」也改用它。
- 图谱的改关系编辑条用同一套整句组件 `RelationRoleFields`。
- 前端称谓表 `RELATION_INVERSES` 是后端 `domain/identity/family_graph.py` 的副本，`membership.test.ts` 直接读后端源码逐项比对。

## 3. 陌生人分流

实测（album3 评测空间）：8 个已确认的人；47 个待确认的面孔里，42 个只出现在 1～2 张照片。
原名录只按出现次数折叠，不看是否确认。

名录分三层（`family/strangers.ts`，纯函数，名录、选人列表、页头共用）：

| 层 | 规则 |
|---|---|
| 我的人物 | 已确认（不论次数） |
| 可能认识 | 待确认，且已有名字或出现 ≥ 3 次（`FREQUENT_FACE_MIN`） |
| 偶遇面孔 | 其余待确认，以及用户标为路人的人（优先级最高） |

- 偶遇面孔默认收起，搜索或筛选时自动展开；名录搜索也匹配别名。
- 「批量整理」支持：
  - 标为路人 / 取消路人标记；
  - 这不是人物：只对待确认的人拒绝其有效人脸分组，需二次确认；
  - 合并为同一人：进入既有的合并确认框。
- 页头计数改为「3 位人物 · 13 位可能认识 · 38 张偶遇面孔 · 1 条已确认关系」，为 0 的层不显示。

**「标为路人」持久化（后端）：**

- 存成通用实体属性 `hidden`，键为 `domain/identity/models.py` 的 `PERSON_HIDDEN_PROPERTY_KEY`。
  走既有的 `PUT /entities/{id}/properties/hidden`，不新增写接口。
- `EntityRepository.person_hidden` 只认布尔真。
- `GET /family-graph` 的人物投影新增 `hidden` 与 `aliases`（OpenAPI 已重新导出）。
- 标为路人不拒绝人脸分组、不删除数据，取消即恢复。
