# 精简记忆图 v3：实现与分阶段验收

## 当前交付边界

本轮实现构图、图路径检索与删除/修正兼容的首版。没有重启服务、重建正式相册图、
修改模型配置或启动 PhotoBench 测评。不得将下面的结构/接线验收表述为回答质量已提升。

## 图契约

- 节点：asset（照片、视频、关键帧）、event、entity（仅已确认人物）。
- 时间、地点、最新 observation、物体/衣着/活动标签及事实断言是属性和来源记录，
  不生成 date/place/concept/observation/fact/hub 节点；权威源表没有删除。
- 保留事件包含媒体、事件来源视频、关键帧派生视频、人物出现在媒体/事件、人物关系。
- 人物别名、属性、家庭角色和人工确认关系来自既有身份/家庭关系仓储。
- 共享物体标签只表示同类标签，不表示同一物件，也不推出因果。一般路径检索不再沿此类边扩散。
- 时序、视觉近邻、同类标签和已有视频因果边仍是不同边族；因果保持证据门槛和方向。
- v3 写入 schema_version=3。现有旧图仍可读，采用新构图器显式重建后才切换节点形态。

## 检索首版

1. 在明确相册内解析已确认姓名/别名或明确事件标题，不依赖普通相似度头部提供人物种子。
2. 对显式人物关系词按源数据方向查询；例如 A 是 B 的父亲，查询 B 的父亲应返回 A。
3. 从人物/事件沿受限的身份、成员和媒体血缘路径找回媒体。
4. 显式锚定的图结果不再仅争取一个尾部槽位，但仍受交付上限、硬条件及现有效用配置约束。
5. 时间/因果问题必须继续沿对应边族，不把“找到这个人的照片”当作因果回答。
6. Agent 获得本页媒体 handle、路径标签及按原方向表述的边；内部遥测另存节点 ID。
   仅为实际交付的媒体提供路径，未交付候选不进入模型上下文。
7. 未解析到明确锚点时，保留普通检索头部的有界拓展；关闭图开关则完全跳过图。

这不是任意自然语言图查询器：多重亲属关系组合、自动解析所有时间/地点约束、
跨照片因果候选生成及完整路径级证据预算尚未实现，需后续独立验收。

## 删除与修正

- 照片删除和视频/关键帧级联删除沿用原正常删除链路，不直接删数据库文件。
- v3 同步清理 surviving event 的 asset_ids 和媒体上已删除事实的来源载荷。
- 共享事件/事实有其他证据时保留，不承诺“删一张照片必然删整个事件”。
- 修正后构图读取当前权威名称、最新观察和有效人工关系；家庭仓储已接入生产构图入口。
- 修正同步原有持久任务及失败重试机制保留，未绕过词法/向量重新索引步骤。

## 第二轮继续验收（2026-11-17）

反向用例发现并修复两项真实问题：

1. 关系词原先从“当前图里已有的边”识别；没有母亲边时，“小明的母亲”错误退化为
   小明本人检索。现改用领域关系词表，并在所需路径缺失时禁止图通道做无约束拓展。
2. “小明和小红一起的照片”原先返回各自照片的并集。现使用确认身份边求交集，
   且交集发生在 limit 截断之前；增加“前面各有 8 张单人照、合影排在最后”的反例。
   交集证据分别保留每个人物的身份边，不以同事件或同标签代替共同出现在媒体中。

本轮标准 pytest 尝试未通过：14 passed、1 failed、36 errors；SQLite 落盘迁移/查询
持续报 disk I/O error，不能当作成功回归。运行时磁盘一度仅剩约 100 MB，交换空间
使用约 15.9 GB。完整相册复制和模型测评均未启动。

为了继续验证代码，改用 SQLite 内存数据库、真实迁移及原有测试函数；检索夹具仅把
测试图片字节写入替换为空操作，不加载嵌入/推理模型。结果：

- 构图/路径相关测试函数：15 项通过（包含上述两个反例及修正重建）。
- 检索编排测试函数：25 项通过（不包含依赖图片文件的效用评分测试）。
- 删除保护测试函数：2 项通过（处理中的视频禁止部分删除、确认身份保留）。
- 额外硬过滤验收：地点萧山区仅保留对应媒体、2099 年排除不匹配证据、
  video 类型排除图片，3 项通过。

合计 45 项内存验收检查通过，不等价于完整 pytest/真实模型测评。
真实相册只读挂载也受到磁盘 I/O 错误影响，因此本轮没有完成真实数据副本的
删除/修正验收，不能把第一轮只读构图结果当作本轮端到端证明。

尚需释放磁盘空间后，重新运行标准专项回归、真实相册副本验收及同题有图/无图模型测评。
本轮未重启服务、未修改正式相册数据库或媒体文件、未加载额外模型。
