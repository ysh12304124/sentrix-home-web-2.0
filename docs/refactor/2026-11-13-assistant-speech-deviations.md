## 影响与失败语义

- `AssistantPanel` 把识别文本追加至草稿；手动停止后自动发送，60 秒超时只填回草稿。
- `SpeechRecognizer` 是前端异步能力边界，`SherpaRecognizer` 实现 Worker 通信、超时和取消；
  `SpeechRecorder` 隔离麦克风资源，`useSpeechInput` 编排加载、权限、录音与转写。
- Worker 使用官方同版本 JS/WASM/data，不在 React 主线程解码；录音最长 60 秒，加载与解码有上限。
- 失败明确显示错误，原草稿保留，文字输入继续可用。取消和会话/相册切换使晚到结果失效；
  取消之后才获批的麦克风音轨也立即关闭。
- 无后端外部契约、配置、数据库、索引和 PhotoBench 变更；无新 Python 模块。
- 官方模型权重由部署准备脚本下载并核验，不提交 Git；部署与性能边界见
  [运行手册](../runbooks/assistant-speech.md)。

## 模型复用与手动停止后自动发送

按用户确认的默认方案，拆分模型与录音资源生命周期：回答忙碌状态不销毁模型，
录音取消、权限拒绝、空结果保留健康模型；卸载以及加载/解码中的取消释放 Worker。
加载 Promise 合并并发初始化请求，旧加载结束不会覆盖取消后重试的状态。
首次加载、刷新页面、异常恢复仍需初始化，不承诺浏览器永久驻留模型。

手动停止识别后将草稿与识别结果合并，通过既有 ask 通道提交；60 秒超时只填回草稿。
ask 返回请求是否被接受，成功后才清空草稿；失败或状态未知保留文字，不自动重试。
同步提交锁防止重复请求，草稿版本和会话检查避免旧请求清空新输入。
初版浏览器记录描述的是当时手动发送行为，本次变更以新增专项回归验证为准。

本次验证：语音专项 23 项通过，TypeScript 与 Vite 生产构建通过；未重新执行实体手机验收。

## 迁移至本机后端推理（后续用户要求，覆盖前述浏览器推理方案）

- 原因：浏览器模型下载、初始化和手机算力开销。SenseVoice-Small 保持不变，
  推理由 API 进程内 sherpa-onnx 1.12.40 执行，不新建独立模型侧车。
  这是用户明确授权的后端启动加载要求，覆盖原有浏览器方案和仅 HTTP 消费模型的默认边界。
- 端口：domain/assistant/ports.py 的 SpeechRecognizer，唯一装配点 Container.build；
  lifespan 启动 load，退出 close；每个请求创建 stream，复用模型，非阻塞锁限制单并发。
- API：新增 GET /assistant/speech/status 与 POST /assistant/speech/transcribe，
  同源认证/CSRF/内部令牌链复用。输入为有界 float32 PCM，输出 text，不改既有问答契约。
- 失败：启动不可用记录日志，状态接口明确上报，识别返回 503，文字仍可用；
  非法音频 400、忙碌 429、推理失败 503，不把异常伪装成空识别，不自动重试。
- 取消：客户端中止 HTTP 并丢弃旧会话结果；已开始的原生调用完成后释放并发槽，
  不声称取消能强杀原生推理，也不卸载共享模型。音频只在本机 API 内存处理，不持久化。
- 部署：路径从 DATA_DIR 派生；准备脚本锁定官方压缩包与各文件 SHA-256，保留许可。
  当前 Mac Python wheel 无 1.12.20，选用实际可安装并通过真实推理验证的 1.12.40。
- 删除旧浏览器模型准备脚本、锁文件和 ASR Worker；保留录音 worklet、自动发送与草稿保护。
- 不涉及模型回答、检索索引、数据库迁移或媒体导入转写；无需 487qa 回答质量对比。
  回滚可恢复上一提交的浏览器识别器与准备脚本，问答历史不受影响。
