# 懒加载与推理模式有限预算改造方案

- 日期：2026-11-18。
- 状态：规划完成，尚未实施。
- 源码核查基线：本机 `feature/photobench-evaluation`，`c565e6cf60f6f696e9d8e44849a136373389d062`。
- 对应任务：T004 评测协议与结果平台、T006 跨平台集成。
- 本轮范围：确定接口、存储和预算契约，列出实施顺序与验收条件；未修改业务源码、运行配置或服务器。

## 采用的方向

懒加载覆盖后端读取与持久化，并延伸到前端的轨迹节点。日常查看只读取轻量状态、统计和题目索引，完整请求响应在用户打开对应节点时读取。后台保存一条新答卷，不再重复写整轮已完成轨迹。

推理模式采用有限的大预算，默认每题最多100次模型生成尝试、600次工具请求；工具额度分为100次搜索和500次其他工具。搜索属于工具请求，搜索一次同时消耗搜索额度和总工具额度。两类额度不能互借，任一上限或时间边界先到即生效。

这些数值是上界，模型可以提前完成；也不保证一题能同时用满各项额度。一次模型响应可以包含多个工具请求，工具数与模型数没有一比一关系。

## 已核实的问题

### 页面已有部分懒加载，后端仍有整轮读取

| 路径 | 当前实现 | 改造要求 |
|---|---|---|
| 运行列表与普通运行概览 | 已有瘦列表缓存、`metadata.json` 及重复请求合并 | 保留有效机制；补齐读写隔离，不再受重轨迹写锁阻塞 |
| 选择特定评分批次的概览、旧汇总重算 | 部分路径仍调用 `_state()` | 改读该批次轻量汇总；缺失索引显式构建 |
| 题目分页 `get_run_items()` | 先读取完整状态，遍历全部题，再筛选和分页 | 直接查询轻量题目索引 |
| 单题详情 `get_run_item()` | 先读取整轮状态，再返回该题的完整轨迹对象 | 只读该题回答和评分，轨迹另取 |
| 前端题目展开 | `useQaPage` 已在展开时请求详情 | 保留题级按需请求，再增加节点级读取 |
| 轨迹节点浏览 | `TraceNodeBrowser` 收到整题对象，本地生成全部节点 | 先读节点索引，点击节点后取输入输出 |
| 切换运行 | `resetPage` 会请求评审和多类分析；图质量目前常驻详情 | 保留可见图质量的轻量汇总，未展开分析的明细延后 |

`load_overview()` 虽然正常只读取轻量元数据，仍与完整快照写入共用 `run_lock`。现有冻结轨迹复用减少了复制与编码，运行中仍重写整份压缩JSON及JSONL；此前实测写入42–61秒，不能靠前端折叠或延长HTTP超时解决。

### 大体积来自长循环和重复上下文

已核长尾样本中，Dover取票码题有2565个逻辑模型步骤、3次成功搜索及2559次被拒的正文读取请求，单题JSONL为334,381,611字节。草莓日期题有2130次搜索请求，其中19次成功、2111次被拒，单题327,701,783字节。

每轮模型输入保存完整上下文，加上上下文检查/恢复记录及多处轨迹投影，累积成单题约330MB。题目和答案本身没有这么大。历史 `model_steps` 也不等于成功HTTP调用次数，改造后需要同时保留步骤与真实尝试计数。

两题临近一小时边界进入收尾，最终均为 `answered_with_gap`。草莓题正式0/1；取票码正文出现正确码但同时表示无法确认，其正式评分因保存等待超时为 `failed/null`，尚不能认定为答对或0分。原记录保持，方案不重判这两题。

### 现有次数字段不能直接充当新的硬上限

- `REASONING_PROFILE` 把五类次数上限设为 `None`，仅保留3600秒墙钟。
- `model_steps` 主要统计主循环和部分评审；规划、上下文重试、部分强制收尾和HTTP适配器重试的口径不一致。
- `tool_round_trips` 包含成功、失败、被拒和回放，但排除 `final_answer`；`inspection_calls` 又只统计成功精读。
- 推理模式提供全工具时，未沿用普通分支的连续失败工具移除。停滞提醒也不会自动结束长循环。

## 推理模式预算契约

### 配置与适用范围

新增推理专属配置，建议字段如下。字段名在实施时与现有配置命名统一。

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `reasoning_max_model_calls` | 100 | 单题共用的生成模型尝试上限 |
| `reasoning_max_tool_calls` | 600 | 单题获准处理的工具请求总量 |
| `reasoning_max_search_calls` | 100 | 上述工具中的搜索请求上限 |
| `reasoning_max_other_tool_calls` | 500 | 上述工具中的其他请求上限 |

四项均校验为有限正整数，推理模式不接受 `None`、0或负数作为“无限”。本地和云端进入推理模式时使用同一契约。普通模式的现有小预算保持；普通云端的 `cloud_unrestricted` 不在本次改动范围内，不能将其原有行为描述为已受新上界保护。

保留当前3600秒产品墙钟及10秒收尾时间，单次请求超时和重试等待受剩余时间约束。测评端3660秒等待与QA并发4保持独立，均不扩大。翻页和精读统一计入其他工具500次，不额外开放无限额度；原有数据权限、取消和失败策略仍生效。

### 模型100次的范围

建议将一次答题引起的全部生成模型请求共用100次，包括规划、主循环、纠错、内部核验、L2评审，以及取证工具内部的VLM生成请求。上下文恢复重试、429/5xx或网络错误后的客户端重发都重新占用额度。一次生成请求只扣一次，禁止外层包装和底层发送重复计费。

额度在调用前原子取得；已经开始的一次尝试即使校验失败、网络失败或响应格式无效，也不退回，防止失败重试绕过上限。尚未取得额度的请求不发送。对服务商内部不可见的重试不虚构次数，记录范围为本系统发起的尝试。

PhotoBench独立的正式ATM/豆包Judge不属于答题Agent预算，继续按冻结评分协议运行。嵌入、检索排序等非生成计算单独记录，不混入生成模型100次。

模型额度中预留最后2次给收尾及其重试，两次包含在100次内。常规规划或工具内部VLM不能使用这2次。若收尾仍失败或没有剩余额度，保存已有证据和明确的停止原因，直接终止，不发第101次请求。`model_steps` 保留为逻辑步骤指标，硬上限由新计数器控制。

### 工具600次的范围

统一分类覆盖所有模型可见工具。搜索类由工具注册信息标识，当前至少包括 `search_memories`；新增搜索工具必须在注册时明确分类，不能改名绕过额度。其余工具归入其他类。

建议新协议把 `final_answer` 也计入其他工具，保证“所有工具最多600次”按字面成立。为交卷预留2次其他工具额度，同时预留2次总工具额度，均包含在500和600之内。旧 `tool_round_trips` 的排除交卷口径保留为历史指标，新预算字段单独展示并标明版本，不能用旧字段宣称已满足新上限。

每个获准工具请求在参数验证与执行前占用一次，成功、缓存回放、无效参数、权限拒绝和执行失败都保留这次计数。一个模型响应含多个 `tool_calls` 时逐项检查，不能在批量执行前只检查一次。

硬条件同时满足：

```text
tool_admitted = search_admitted + other_admitted
model_attempts <= 100
tool_admitted <= 600
search_admitted <= 100
other_admitted <= 500
```

到达上限后，额外提议记作 `budget_denied`，不再取得额度或执行。分别展示“模型提出数、获准请求数、实际执行数、预算拒绝数”，避免把2111次被拒请求称为实际搜索。子类额度不能互借，例如搜索用满100次后，剩余其他额度只可用于其他工具。

### 停止与失败工具处理

1. 每次提供工具集前，根据剩余额度和既有连续失败策略移除不可用工具；执行入口再次检查，覆盖模型使用过时工具定义的情况。
2. 搜索额度耗尽后关闭搜索，其他工具仍可使用。其他工具额度进入交卷预留区后，只允许交卷，必要时可继续搜索，前提是尚有搜索、总工具和模型额度。
3. 常规总工具或模型额度用完，进入收尾；时间进入收尾窗口也执行同一流程。收尾期间不再检索或精读。
4. 记录触发上限、已用/上限、剩余证据与未满足需求。保留 `answered` / `answered_with_gap` 等结果语义，另加明确预算停止码，不能把被迫终止标成完整完成。
5. 本轮先落实既有连续失败移除及次数硬上限。新增“连续N轮无新证据即停止”需要另行用正常多跳样本验证，本方案不任意增加小阈值。

预算对象按 `turn_id` 隔离，并由规划器、工具和模型适配器显式共享。禁止修改全局共享模型客户端的额度，防止四个并发题互相扣账。发送前的尝试编号和额度消耗进入小型追加记录；同一题恢复时沿用计数，不重新赠送100/600。完整题目重测则使用新的turn及明确的新预算版本。

## 懒加载与持久化设计

### 五层读取

| 层次 | 默认内容 | 按需内容 |
|---|---|---|
| 运行列表/状态 | 状态、进度、型号、预算版本、核心汇总和更新时间 | 不携带答卷及原始轨迹 |
| 题目分页 | 题号/UUID、题干摘要、执行/评分状态、分数、耗时、调用统计及轨迹节点数 | 完整回答与附件列表 |
| 单题核心 | 该题原题、回答、选定评分/理由、证据引用和预算结果 | 轨迹、请求体和响应体 |
| 轨迹索引 | 节点ID、类型、父节点、时间、状态、token/耗时、短预览 | 节点完整输入输出 |
| 节点内容 | 用户点开的节点及字段 | 大字段分块查看，原文完整导出 |

建议保留现有运行与题目路由，明确轻量响应契约；新增节点接口：

```text
GET /runs/{run_id}                                   # 轻量汇总，可选评分批次
GET /runs/{run_id}/items?page=...&page_size=...        # 轻量索引筛选、分页
GET /runs/{run_id}/items/{item_index}                 # 只含单题核心
GET /runs/{run_id}/items/{item_index}/trace?cursor=... # 节点摘要分页
GET /runs/{run_id}/items/{item_index}/trace/{node_id}  # 单节点元信息
GET /runs/{run_id}/items/{item_index}/trace/{node_id}/content?field=...&cursor=...
```

运行列表和 `/active-work` 继续使用轻量路径，并保留真实worker探测。详情响应拆分涉及的前端类型和消费者同期更新；完整轨迹通过显式节点/导出接口获取，不保留默认回传整轮数据的兼容分支。大回答、附件长列表也采用有明确标记的分块读取，全文可取，不静默截断原始内容。

### 文件分离与提交

继续沿用本地文件存储，不新增数据库服务。持久化拆为少量可变轻文件与独立内容对象：

- `manifest` 指向一个已提交版本，记录格式及revision。
- `overview` 保存运行信息，以及按评分profile/batch区分的轻量汇总。
- `qa-index` 保存全题集的小摘要，可用于筛选、facets和分页，不含轨迹正文。
- 每题回答内容独立；评分按题和batch独立；轨迹节点索引与原始内容独立。
- 未完成题的事件和模型尝试追加写入，完成后固定引用；新检查点只写新增或变化部分。

重内容写入和索引构建在发布锁外完成，最后短锁原子替换manifest指针。读取请求先固定一个revision，该响应内的题目、统计和分数都来自这一版本。读线程不等待整轮压缩，旧版本在读者/导出仍引用时保留；进程崩溃后只暴露已提交版本，未提交文件可识别并恢复处理。

只存一份规范轨迹，`runtime_turns`、`trace_bundle` 与 `debug_calls` 等展示投影使用节点引用，导出时恢复原字段。原始请求的消息顺序、内容和来源必须完整保留。首版先消除重复投影与重复写入；跨轮相同消息的按内容去重只在实测仍有必要时追加，不先实现复杂差分链。

完整JSON与JSONL改为显式导出任务，按已固定revision流式拼装，可缓存相同版本的导出结果；不在每次保存时重复生成两份全量文件。恢复、补评、离线分析和两种导出都需直接支持新存储，不能让这些后台路径再次将整轮内容复制进内存。导出失败单独报告，不应将已经持久化的答题阶段改判失败。

### 指标和筛选

选评分批次也只读对应汇总，不调用完整 `_state()`。分数更新按 `qa_id + batch_id + revision` 替换旧贡献，恢复与补评不能重复累计。全部统计口径保持，包括正式交付QS、工具候选QS和R@5。

均值、计数和分布可增量维护；P95等需要完整样本的精确统计使用独立的紧凑数值数据，不加载轨迹，也不暗改为近似值。汇总里的逐题预算数组等明细移至分页接口，统计卡片只带聚合值。分析面板按需读取独立汇总或索引，不能在切tab后又触发整轮解析。

### 前端请求与缓存

保留现有题级展开，再将节点输入输出读取移动到点击事件。节点列表分页，页面只保留正在查看的节点及小范围近期内容；长内容分块渲染，避免一次挂载上千轮完整上下文。

切换运行时先请求可见汇总及当前题页。未展开的记忆分析、关键帧分析和评审明细延后；常驻图质量卡片读取轻量汇总。历史曲线按既有开关和可见性读取。缓存键至少包含run、qa、评分batch及revision；切换运行取消过期请求，轮询只刷新轻量状态，并对变更题目失效缓存。

### 历史兼容与迁移

旧run原件保持，显式一次性构建派生索引与独立内容。索引缺失时返回“索引构建中/失败”的明确状态，不在每个HTTP请求里自动解析GB级文件。迁移记录来源SHA、格式版本与条目数，导出还原后按字段及原始内容SHA验证。

正在运行的旧格式测评不热迁移，不通过新默认预算改变其行为。旧run续跑沿用冻结预算及历史口径；旧数据没有记录的真实请求次数标为未记录，不从逻辑步骤伪造补全。新格式和预算版本由新run/turn显式冻结。

## 验收标准

### 有限预算

- 第100次模型尝试可在预留规则下发送，第101次不能发送。规划、上下文错误、内部评审、VLM和HTTP重试均有边界用例。
- 搜索100、其他500、总工具600同时成立；包含失败与回放，交卷计入其他额度。单个响应提出700个工具请求也不能越界执行。
- 搜索用完后其他工具可继续，子类不可借额；工具集合移除预算耗尽或连续失败的工具。所有工具均能分类。
- 收尾占用预留额度，失败后不会额外补发；时间不足、取消和预算不足可以明确终止并保存已成证据。
- 四题并发预算互不干扰，同题恢复计数不重置；旧冻结run保持原预算；正式Judge不扣答题额度。
- 用已保存的Dover/草莓长尾输出离线回放，验证新逻辑会有限收尾。回放只能证明边界行为，不能宣称新答案正确率；本轮不新建真实推理测评。

### 懒加载与保存

- 真实64题重轨迹样本及1013题夹具均验证。列表、概览、评分切换、题目分页和单题核心路径将 `load_state()` 设为报错后仍能正常读取。
- 单题核心不含 `runtime_turns/trace_bundle/debug_calls` 原始载荷；节点页最多50条短摘要，单条预览不超过2KiB。完整内容仅由明确的字段请求或导出返回。
- 建议目标：运行概览/列表响应P95≤500ms、P99≤2秒；20题分页P95≤1秒、P99≤3秒。测试48并发轻读，同时进行4题写入和1个流式导出，持续10分钟；记录机器、冷热缓存与失败率，不将目标写成已实现收益。
- 列表单页与20题分页未压缩响应目标各≤256KiB；概览只含聚合值。节点大字段每块≤256KiB且可完整拼回。复杂筛选也只扫描轻索引。
- 48并发轻读的进程内存增量目标≤256MiB，且不得出现每请求复制整轮轨迹；分别记录RSS、峰值和基线。未达标先定位索引或缓存对象，不把整轮数据改为永久常驻。
- 保存一条新答卷不重写旧题重内容；连续保存量与新增内容近似相关。故障注入验证提交前后崩溃、索引中断和恢复，不暴露半版本。
- 新旧两种完整导出、恢复后原答卷、评分batch/有效分和失败历史按字段/内容SHA对齐；均值及精确分位数一致。所有模型/工具原文仍可取回。

## 发布边界与后续接手
