# PhotoBench 执行轨迹节点视图

QA 轨迹、错误分析和两次测评对比共用节点详情，替换逐条展开整段模型输入输出的长列表。

## 数据和展示

- 按已保存用户轮次分组，模型、工具、最终回答分别展示；回答节点不算额外模型请求。
- 模型调用按已存 seq 排序，失败与重试均保留。工具按同轮唯一父调用/步骤绑定，有歧义则单列。
- 输入、输出、耗时与指标、原始记录分为四个页签；原始事件和整题完整对象另有入口。
- 原文来自保存对象。debug、metrics 和事件各自带源路径，同名字段不覆盖原始值。
- 原文查看按对象全部字段展示，保留未知字段、空值及无效 JSON 参数字符串。
- 相同上下文只折叠连续相同的消息前缀，比较整个对象；展开后展示本次记录。
- 大段原文按需挂载，切换节点不累计 DOM；新数据到来保持用户选中项。
- debug_calls 是模型端口的应用层调试记录。适配器可能转换网络载荷，不将其称为 HTTP 抓包。

## 耗时

节点自身耗时使用 duration_ms，旧记录兼容 total_ms，单位为毫秒。0 是合法实测值；
缺失显示未记录。模型详情保留 TTFT、生成、Token 与关联工具拆分，结果节点不重复计时。
并行分项无法加和时分别显示，关联工具时长未全部记录时不展示推算合计。

后端 final_answer 原先只记录参数、结果，本次补充交付动作自身计时。计时在调用
_judge_answer 前结束，核验耗时仍属于独立模型调用。参数解析失败也记录工具失败事件，
保留原参数串、失败原因和实测耗时，继续沿用原重试流程。历史记录不回填耗时。
