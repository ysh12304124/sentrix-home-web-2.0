# PhotoBench 错误分析与报告（现行规则版本10）

## AI证据与提示词4（2026-10-29）

逐轮GT与预期行为单列为`iN:task_contract`，优先放入有限证据预算；总览也独立接收`task_contracts`并允许引用，避免沿用案例对任务要求的错误概括。`answer_and_refuse`分别核正常回答与应拒绝请求，正常JSON格式和披露内部上下文分开判断；未泄露系统提示/工具说明不能当缺陷或缺失证据。候选身份和因果未验证的限定同样适用于建议。

提示词升级为`analysis-claims-4`、证据版本4，旧报告与旧配置指纹保持，新版本不能复用旧版本诊断缓存。既有outcome仍独立保留逐轮最终回答及恢复unknown。引用有效、执行完整和AI归因质量分别验收；真实样本安全要求定向修复通过，候选身份/因果质量仍待独立闭环，不据此放行全量。

错误分析为测评结果的派生读模型，不写回原分数、GT、Agent预算和恢复策略。入口为运行详情的“错误分析”，默认先展示全部题目的回答结果与分类表现。普通测评/重评分收尾后自动排队，历史记录手动生成；失败、取消、中断和仅构建相册的运行也可分析，后者仅报告导入与处理阶段。

## 分层与生命周期

- `domain/error_analysis/rules.py`：分类、去重题数、逐轮行为、覆盖分组、检索信号、逐题配对。`exports.py`输出离线HTML及JSON/CSV。
- `application/error_analysis/service.py`：自动触发、显式选择分析provider；通过`AnalysisBackend`端口编排。
- `infrastructure/error_analysis/backend.py`：结果根目录下`.analysis/<job_id>`持久化任务、案例索引和报告，单个spawn子进程，最多32个待执行任务。新测评/重评分优先，执行中的分析在逐题检查点暂停。AI单次请求连接超时10秒、读超时45秒，无法撤回已经发出的请求；取消确认仍以工作退出为准。
- `worker.py`：读取已提交JSONL，先固定私有输入，逐题分析、保存轻量案例；不在HTTP请求或遥测采样线程加载原始轨迹。老式仅run.json结果在隔离子进程内兼容读取。导出扫描轻量索引，完整原始轨迹按需通过既有逐题接口读取。
- `bootstrap/container.py`唯一构造依赖；API与前端只操作任务和派生产物。

测评/评分与受管采样收尾→释放原工作→排队分析→固定输入→规则聚合→提交完成状态。分析失败、取消、中断不会改变原run终态。分析任务进入`active-work`、`cancel-active`和服务退出确认。重启将遗留活跃任务标记`interrupted`，用户可以重试，不假装已完成。

报告记录规则版本、生成时间、源代码版本、结果SHA256、GT指纹、源文件修订和覆盖情况。结果、元数据或重新评分变化会标记过期，旧产物保留。新对比和AI任务拒绝使用过期规则报告；已生成的对比/诊断也随来源过期。原始轨迹接口始终返回当前保存事实，旧报告排查时须先核对来源。

## 统计与证据

质量分数0/1/2/缺分、执行正常/失败/取消/未知、评分故障分别统计；题数、对话轮、模型调用、工具调用、已记录参数JSON各有独立分母。每类异常保存事件数、受影响题数、最终执行失败题数及明确恢复题数，类别允许重叠。

上下文软预算预检、窗口超限、输出空间不足、输出截断和未知子类分开；工具参数非法、模型格式错误、服务响应JSON错误和Judge输出错误分开。`parse_failure`没有证据时归未知解析失败。历史文本识别标记`legacy_text`；结构化记录优先。事件引用包含题索引、轮次、步骤、角色和调用ID。恢复只认同轮同角色同一步重试成功等明确证据，最终回答成功不自动证明所有异常已恢复。

题型、任务类型、难度、角度、可回答性、预期行为、媒体类型、单/多轮分别报告。多标签分组可重叠；未覆盖行为不算0%正确，未知标签不补造。逐轮行为筛选同时要求预期与实际在同一轮匹配。

检索有GT才判断候选未命中；候选命中未交付、交付后低分分别展示，均为定位信号。源报告还显示阶段错误、保存错误、遥测完整分量与有效样本数；缺失历史数据保留未知。

## 新调用事实采集

主Agent、规划器和Judge追加可选诊断字段及唯一逻辑调用ID。`RecordedPhotoInspector`是可选观测端口，以调用局部ContextVar收集工具内部模型的请求、超时、格式、HTTP及token事实；保留原inspect接口和原失败回退。预算采用调用前已经计算的估计值及响应usage，不重新制定预算。不改变提示词、重试、压缩或恢复策略。旧记录缺字段保持未知；一次逻辑调用内的底层HTTP重发尚未全部展开为独立transport attempt。

## API契约

均在`/api/v1`，类型见OpenAPI `AnalysisJob/AnalysisReport/AnomalyEvent/CaseReference/CasePage/ComparisonReport/DiagnosisReport`。

| 接口 | 用途 |
|---|---|
| POST `/runs/{run_id}/analysis` | `kind=rules/compare/ai`创建后台任务；202 |
| GET `/runs/{run_id}/analysis` | 最新规则任务及报告、过期标记 |
| GET `/runs/{run_id}/analyses` | 历史任务，保留旧来源 |
| GET `/analyses/{job_id}` | 任务进度与完成报告 |
| POST `/analyses/{job_id}/cancel` | 请求取消，工作查询确认退出 |
| GET `/analyses/{job_id}/cases` | 分页，按异常类别/题目形式/任务类型/角度/难度/可回答性/媒体/对话/行为/分数/恢复/执行状态筛选 |
| GET `/analyses/{job_id}/export?format=html/json/csv` | 来源、统计、筛选条件和案例摘要；不默认附完整轨迹 |

JSON/CSV/HTML的案例筛选使用同一规则。规则9起，统计、案例、导出与AI分析范围使用同一筛选谓词；统计涵盖全部匹配题目，与当前页大小无关。HTML无CDN依赖，使用原生条形图/表格/折叠案例；所有原始文本转义，CSV防止公式执行。交互页面提供结果概览、题型与标签、执行问题、回答行为四视图，并按需读取固定报告的原始步骤。主视图使用任务完成质量2/1/0分及未评分（适用回答、拒答、澄清）；满分率以有效质量评分题数为分母。内容题型仅使用明确的内容任务标签（媒体检索、事实问答、统计枚举、事件总结），不把行为测试与内容任务并列。原始混合的task_type/question_type不作为质量图分组；角度、难度、可回答性、媒体与对话形式各自独立。回答行为单列逐轮分布和符合率，不从质量分推算。

## 两轮对比

以非重复QA ID及题目、GT和逐轮对话定义指纹配对；缺ID/重复ID、定义变化、单边未匹配单列。展示质量变化、执行状态变化和异常新增/消失。Judge配置/已记录系统提示词指纹与预算不一致或缺少关键配置时，不给出“版本提升”汇总。设备、模型、代码版本差异保留，不作因果归因。

## 按需AI诊断

默认关闭。用户显式选择模型与范围后启动：`mode=overview|cases`，`scope=run|filter|selection`，`max_cases=1..100`（默认12）。服务端固定题目ID；并发1，单请求读超时45秒、连接10秒，临时网络/5xx最多两次，4xx不重试，配置/鉴权错误停止后续请求。密钥只在进程内传递。

领域策略负责代表抽样、输入预算与提示词；基础设施负责HTTP和保存。抽样覆盖工具/原因、分数、恢复与能力，预算允许时保留正常满分反例。每题输入由固定快照构成，保留原始路径与省略清单；输出为独立命题（记录观察、待验证假设、建议），逐条校验引用。引用合法不等于语义已审核。全量问题数量与调用去重由程序计算，AI汇总只可引用事实组或合格案例；输入裁剪有明确记录。

单题超时、非法JSON或非法引用分别记录并继续；保存引用合格/无效/失败/未处理和实际请求usage、耗时。`resume_job`在来源、规则、提示词、模型端点配置指纹相同才复用成功项；`summary_only=true`只重做归纳。旧诊断保留可读，提示词版本变化标记过期。取消后可导出已有诊断，刷新后从历史任务恢复。

首版不包含跨多轮历史趋势、自动修Agent、自动重评分或PDF/Word。案例摘要文本单字段最多8000字并标记截短；完整轨迹保留原接口。大报告导出为显式同步操作，只扫描派生索引；规则分析和模型请求全部在受管子进程中。

## 结果浏览与操作便利性（2026-10-24）

案例与HTML/JSON/CSV导出共享`content_type/angle/difficulty/answerability/media_type/conversation_type`过滤；原始`task_type/question_type`查询仍兼容；`score=low`只包含0/1分，不含未评分；`anomaly=yes/no`只描述是否有已记录事件。旧查询兼容。规则版本3在逐题提取时按明确别名统一任务类型，同题重复别名先去重，再汇总；筛选与导出沿用同一分类。原始QA和GT指纹保留原值，版本2旧报告标记过期并保留，重新生成新报告。

AI支持全选本页、选择当前筛选前20题、未完全答对题和运行异常题；选择不发模型请求。下一批可跳过本报告本次会话中已有效诊断案例，单批仍≤20；跨页选择可见计数，切换过滤/报告清空选择。模型仍需显式选择并确认。

两轮对比从分页历史运行下拉选择，按日期/模型/题集搜索已加载记录，可加载更早记录；排除本轮、活跃运行和仅构建任务。另一轮缺报告或报告过期时，通过现有后台规则任务自动准备，完成后再创建对比；准备失败显示原因，停止等待不取消共享规则任务。对比方向固定为“所选另一轮相对当前基准”，关键配置不全时仍不作版本提升结论。

任务类型中的`T1_retrieve_media/T1_media_retrieval/media_retrieval/媒体检索`统一为`T1_retrieve_media`。其他明确别名见domain的`taxonomy.py`，不按题目内容推断。显示名称统一简洁中文；`behavior`只保留为原始行为测试标签，不进入内容题型分布。主页面保留结果卡片和分类堆叠图，移除重复结果图及阅读说明；统计定义、检索细节折叠，只有多标签重叠时提示。窄柱段不强行排数字，表格与悬浮仍提供完整数值。

点击统计卡片、图表或分类表数字后，更新过滤条件、回到第一页并将焦点及视口定位到题目列表；加载中不展示旧命中数。案例及分页紧随筛选工具，AI与两轮对比在案例之后，避免筛选结果被操作区隔开。下拉筛选不自动移动页面。

分类表现支持双向查看：“按题型看得分”保留各类得分堆叠；“按得分看题型”选择2/1/0/未评分，按所选得分下各类题数降序展示，比例分母固定为该得分的全部题数。支持原有分组维度、题数/占比切换及点击查看案例。无该得分题显示空状态，未记录分类如实提示，多标签重叠时提示比例可能超过100%。只读取已有报告，不改变统计规则和评分。


## 分类维度与行为口径（2026-10-24修订，规则4 / schema2）

- `groups`仅含`content_type/angle/difficulty/answerability/media_type/conversation_type`。内容类型来自明确task_type白名单，不按题目文本推断；无内容标签的行为题计为未标注。`source_labels`保留原始来源，GT、结果和配对指纹不变。角度中明确的内容任务标签（如event_summary）也计为未标注角度。
- 按得分看内容题型：分母为该得分已标注内容类型的题数；全部/已标注/未标注题数同时展示。其他维度比例分母为该得分全部题数；多标签可重叠，明确提示，不伪称合计100%。
- `behavior_groups`按预期动作统计全部对话轮（answer/clarify/refuse/unknown），各组total合计为turns；每组valid/correct/incorrect/missing独立于质量分，符合率以valid为分母。多轮各轮分别统计，不能取顶层最后轮标签代替全对话。无样本显示未覆盖，失败Judge残留动作不计有效判定。矩阵包含全部轮与未知值。
- `behavior_scenarios`从明确question_type场景标签提取（多轮澄清、证据不足、指令注入等），可重叠；不与动作平级，也不组成单一100%。未标注场景保持未知，不等同普通/非攻击。
- `heatmap`使用去重后的`content_type`单标签键，避免多标签拼接导致轴匹配失败。点击行为格子按`expected_action/actual_action/behavior_result/test_scenario`同一轮联合匹配；返回题目去重，因此轮数和题数可能不同。JSON/CSV/HTML共用筛选；CSV包含逐轮行为与派生内容类型，原始标签仍可溯源。
- 规则3旧产物保留并标过期，旧报告页面要求重新生成，不复用混维度图。独立生成规则4报告，不重评分、不写回原结果。

## 系统能力分组（规则8，2026-10-28）

`ability_family/ability_type/benchmark_group`维度用于题级及逐轮分布、API筛选、分页和JSON/CSV/HTML导出。页面默认一级能力，可展开普通二级；H抗幻觉、I抗注入攻击在v2进入一级统计，二者暂不细分，不提供空的二级下钻。原内容分类可独立查看。

题级主能力是回答轮并集，质量分使用原题级最终质量分；逐轮取该轮保存标签和质量分。轮级多条件须在同一轮满足，案例按题去重。支撑能力不进主标签分母。一级有效分母`ability_family_valid/turn_ability_family_valid`在v2包含全部已分类题或轮；二级`ability_valid/turn_ability_valid`仅含普通回答。按分数对应`qa_ability_family_score_* / turn_ability_family_score_*`及`qa_ability_score_* / turn_ability_score_*`。跨一级、同一级多二级均只计一次分母，下钻分母取对应family去重计数。

案例和报告保存`ability_taxonomy_version(s)`及`ability_labels`，前端、QA详情、CSV和HTML使用保存版本名称。V1记录仍用12类和特殊能力不适用规则；旧规则7报告使用v1字典。混合版本报告明确展示两个版本的冲突名称，不能把共用代码解释为同口径比较。比较标签指纹不同的记录不产生改善汇总。

规则8将旧报告标记过期并保留；重新生成只派生新报告，不重评分或回填原run。分类完成与QA内容、选项、引用及证据质量验收分别记录，类型低分也须结合轨迹再判模型或工具的具体原因。


## 规则9接口与筛选（2026-10-29）

- 新增 `GET /analyses/{job_id}/view`，返回分页案例、完整筛选范围的summary、调用去重问题组issues、工具统计tools、全来源facets和一级/二级能力树。原cases接口保留。
- 新增 `GET /analyses/{job_id}/evidence/{index}`，读取规则任务保留的input.jsonl快照并附结果指纹。快照仅随分析产物保留，逐行读取；旧报告无快照返回明确错误，要求重新生成，不转读当前run。业务历史结果、GT及分数不修改。
- 新筛选 `tool_name/issue_kind/failure_reason/component/signal/q/index/turn` 与原筛选共享域规则。工具+原因+恢复必须同事件，行为条件必须同轮，事件与行为也必须同轮。仅工具筛选包含成功调用；附加问题条件只匹配问题事件。非法查询键和受约束枚举返回422。
- 事件明确工具名称、外层调用、内部model_call_id、parent_step_id、来源位置及关联事件ID；工具调用以记录位置去重，多个内部错误不增加外层调用分母。没有调用身份的历史记录不补造；问题组关联调用数只计已知调用。
- `no_text_detected/photo_not_found/asset_not_found`归证据不可用，拒绝权限归策略限制。恢复需明确重试/恢复记录；最终正常结束不能证明某次异常已恢复。
- 题级分数以最终任务计算，行为及轮标签以匹配轮计算。summary的总体调用分母是匹配题的完整调用数（`call_count_scope=matching_cases_all_turns`）；tools表调用数为匹配轮、所选工具内记录，affected_calls为其中匹配问题调用。两类分母分别标明。
- 所有筛选直接生效、可移除、写入URL并支持返回；相关题按钮叠加筛选。分类按保存的版本展示；难度、行为与能力各自独立。

### 验证边界

自动测试使用本地HTTP模拟，不默认向配置模型发送分析请求；真实历史回放与浏览器验收记录单独归档。AI事实解释仍需人审核，接口仅作结构、引用归属与来源一致性检查。

证据包v2包含已保存的`trace_bundle.debug_calls`模型输入返回，以及证据账本、claim核验、检索候选和任务状态。
输入按字符预算裁剪并记录省略；模型IO/账本的保存可用性单列，未保存不得补造。
AI提示词`analysis-claims-2`；汇总接收全范围得分、行为与检索信号事实，`scope:statistics`引用可在页面和导出中核查。

## 规则10：题型标签分析与图形（2026-10-29）

现行能力字典为 `ability-2026.10.28-v2`，5个一级、10个普通二级。页面按运行保存的版本解释标签；版本与缺标覆盖常显，测试分组进入常用筛选。标签分析可切换一级能力、二级能力、普通/抗幻觉/注入测试分组，以及难度、可回答性、媒体、对话和历史内容标签，各维度独立。支撑能力不加入主能力统计，特殊题及普通澄清轮的二级为不适用。

新增只读报告字段 `group_partitions[qa|turn][dimension]`：total、labeled、unknown、not_applicable、multi_labeled、exclusive、exhaustive。逐个对象检查所属集合，未知/不适用各有显式组；exclusive 表示每个对象仅有一个成员，exhaustive 表示非空范围已全部分组（包括未知组）。不能用类别数量之和等于总数推断互斥。`group_errors` 按 unit/dimension/value/code 返回受影响题/轮数，同一对象同类问题去重。groups 与 turn_groups 增加 affected 和 failed 数量，保留原字段；后者按相同轮次关联。标签版本也可用于 cases/view/export/AI scope 筛选。

图表提供类内得分堆叠图（数量/比例）、题目构成图和标签×执行问题矩阵，数值表同步可读。只有逐对象检查确认互斥且覆盖范围时，构成图可使用环形图；多标签及未保存检查结果的旧报告用条形图。得分构成天然互斥，独立显示含未评分的环形图。多标签比例以当前全部题/轮为分母，合计可超100%。筛选/矩阵点击/分页/导出仍共享同一范围；题级用最终分，逐轮用本轮分。混合能力版本先按版本筛选，不将同名代码当成同一分类解释。

分析worker可以从**同次运行已冻结的qa_snapshot.rows**恢复结果条目漏存的能力字段，要求题号、单轮题干或完整逐轮消息匹配；已有版本优先保留，重复题号/对话不完整不补。案例记录 ability_annotation_source=run_item/run_qa_snapshot/unrecorded。原始结果和固定轨迹文件不修改，不按题号读取当前题库覆盖历史。历史没有可验证标签则继续未知。规则版本变化使旧报告过期，重新生成只产生派生报告。
